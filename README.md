## Мета роботи

Дослідити, як у локальній мережі за відомою IPv4-адресою визначається MAC-адреса. Навчитися переглядати й очищувати ARP-кеш засобами операційної системи, аналізувати пакети у Wireshark і складати тест-кейси для перевірки ARP.

Для варіанта 1 перевірено, що після отримання **ARP Reply** у таблиці Windows з'являється динамічний запис з IP- та MAC-адресами MacBook. Додатково перевірено обмін із використанням уже відомої MAC-адреси.

## Середовище

| Пристрій   | Підключення | IPv4-адреса     | Маска           | MAC-адреса          |
| ---------- | ----------- | --------------- | --------------- | ------------------- |
| Windows ПК | Ethernet    | `192.168.0.227` | `255.255.255.0` | `00:e2:69:6e:ee:17` |
| MacBook    | Wi-Fi       | `192.168.0.147` | `255.255.255.0` | `2a:2c:4d:45:ca:04` |

Обидва пристрої підключені до локальної мережі `192.168.0.0/24` через маршрутизатор `192.168.0.1`. Захоплення виконано у Wireshark на Ethernet-інтерфейсі Windows.

## Основна перевірка — оновлення ARP-кешу

У PowerShell з правами адміністратора виконано:

```powershell
arp -d 192.168.0.147
arp -a -N 192.168.0.227
ping -n 4 192.168.0.147
arp -a -N 192.168.0.227
```

Після видалення запис для `192.168.0.147` був відсутній. Під час `ping` Wireshark зафіксував:

1. ARP Request №1474: `Who has 192.168.0.147? Tell 192.168.0.227` — широкомовний запит Windows.
2. ARP Reply №1477: `192.168.0.147 is at 2a:2c:4d:45:ca:04` — відповідь MacBook.
3. Чотири пари ICMP Echo Request / Reply; втрат пакетів немає.

Після відповіді ARP-таблиця Windows містила динамічний запис `192.168.0.147 → 2a-2c-4d-45-ca-04`. MAC-адреса в таблиці збігається з полем **Sender MAC address** в ARP Reply. Різниця між двокрапками та дефісами зумовлена форматом виводу програм.

Фільтр Wireshark для ARP-обміну з MacBook:

```text
arp && (arp.src.proto_ipv4 == 192.168.0.147 || arp.dst.proto_ipv4 == 192.168.0.147)
```

**Результат тест-кейсу TC ARP 01: Passed.**

## Додаткова перевірка — наявний ARP-запис

Без видалення запису повторено дві серії `ping -n 4 192.168.0.147`. У захопленні видно вісім ICMP-запитів і вісім відповідей. Після початку обміну Windows відправила одноадресний ARP Request №943 на вже відому MAC-адресу `2a:2c:4d:45:ca:04` та отримала ARP Reply №944. Нового широкомовного пошуку MAC-адреси MacBook у показаному захопленні немає.

Фільтр для спільного перегляду ARP та ICMP:

```text
arp || (icmp && ip.addr == 192.168.0.147)
```

**Результат тест-кейсу TC ARP 02: Passed.** Наявність запису в кеші не виключає одноадресних ARP-перевірок доступності сусіднього вузла.

## Очищення кешу

Окремо переглянуто таблиці всіх інтерфейсів та виконано загальне очищення:

```powershell
arp -a
arp -d *
arp -a
```

У таблиці Ethernet-інтерфейсу після команди зникли динамічні записи `192.168.0.147` та `192.168.0.242`. Запис маршрутизатора `192.168.0.1` залишався у повторному виводі або міг швидко відновитися через фоновий трафік. Частина службових multicast-записів також залишилася; для цієї перевірки повністю порожня таблиця не потрібна.
